ARM64 主要指令：读懂一个数组循环

先确定操作数代表什么

ARM64 通常指 AArch64，本课读的是它的 A64 指令。遇到一行汇编，先圈出读取的值，再标出写回位置。多数算术指令把目的寄存器写在第一项；str w8, [x0] 的第一项却是要存入内存的数据，而 cmp 写的是隐含的标志。

  • x0…x30 是 64 位通用寄存器，w0…w30 是对应的低 32 位视图。写 W 会把对应 X 的高 32 位清零。例如原来 x8 全是 1，执行 mov w8, #1 后，整个 x8 等于 1。
  • xzr/wzr 读作零，写入结果被丢弃。sp 指向当前栈顶。立即数前缀 #，方括号表示访问该地址的内存。
  • 在本课 Linux AArch64 调用约定中，简单的整数和指针参数依次从 x0–x7 传入，整数结果从 x0 或 w0 返回。x30 也叫 LR，保存链接地址。浮点和向量参数另走 SIMD/FP 寄存器。Arm AAPCS64，Machine Registers 与 Parameter Passing

算术与位运算：看一个数怎样流过三条指令

mix(a,b,c) 计算 ((a << 3) ^ (b & 255)) + c。在下列编译输出中，假设 x0=3、x1=0x10f、x2=5。

and  x8, x1, #0xff       // x8 = 0x0f，只留下低 8 位
eor  x8, x8, x0, lsl #3  // x8 = 0x0f XOR 0x18 = 0x17
add  x0, x8, x2          // x0 = 0x1c，即 28
ret

and 取两边共同置位的位，orr 合并置位，eor 保留不同的位。这里 lsl #3 修饰 EOR 的右操作数，x0 此时仍为 3。要判断能否把两行 IR 放进一条机器指令，先看消费者允许怎样修饰输入。

lsl 左移补零，lsr 右移补零，asr 右移复制符号位。按 32 位计算，0x80000000 右移一位，逻辑结果为 0x40000000，算术结果为 0xc0000000。正数 8 右移时两者同为 4，因此只测正数无法区分它们。

sub 做减法，mul 保留乘积的低目标位宽，madd xd,xn,xm,xa 计算 xn × xm + xa。实测 scaled(3,5) 的函数体为 mul x0,x0,x1 和 ret。同一目标文件关闭别名显示后，乘法写成 madd x0,x0,x1,xzr。把零代入第四项，便能解释两种拼写为什么对应同一条编码。

扩展到宽整数时，adds 在加法后写 NZCV，adc 把当前进位 C 加入下一段。以两个 64 位字表示 128 位数，低字全为 1 再加 1，低字回到 0、C=1，高字用 ADC 加上这 1。对应的机器指令与进位边见宽位加法实测。

访存：用地址、宽度、写回解释 LDR 和 STR

bump(p,i) 给一个 32 位数组元素加 1。假设 p=0x1000，i=2，地址 0x1008 中的 32 位值为 9。

ldr w8, [x0, x1, lsl #2]   // 地址 = 0x1000 + (2 × 4)，取 4 字节
add w8, w8, #1            // w8 = 10；此时内存仍是 9
str w8, [x0, x1, lsl #2]   // 地址 0x1008 的 4 字节更新为 10
ret

方括号内的移位把元素索引换算成字节偏移。此形式保留 x0。另一种 ldrsw x9,[x0],#4 先从旧 x0 读 4 字节，符号扩展到 64 位，再让 x0 前进 4。若内存的位模式为 0xfffffffe，ldr w9,[x0] 得到 x9=0x00000000fffffffe，LDRSW 得到 x9=0xfffffffffffffffe。两者读了同样多的字节，差别在写入目的寄存器时如何扩展。

常见变体还有 ldrb/strb（1 字节）、ldrh/strh（2 字节）和 ldp/stp（连续读写两个寄存器的值）。例如 stp x29,x30,[sp,#-16]! 先减小 SP，再将两个 64 位值依次存到新 SP 与新 SP+8。

把指令连起来：累加数组中的正数

positive_sum(p,n) 的 x0 是第一个 32 位有符号元素的地址，x1 是元素个数。以下为实际输出，标签按作用重命名。

    mov   x8, xzr
    cbz   x1, done
loop:
    ldrsw x9, [x0], #4
    cmp   w9, #0
    csel  x9, x9, xzr, gt
    subs  x1, x1, #1
    add   x8, x8, x9
    b.ne  loop
done:
    mov   x0, x8
    ret

用数组 [-2,5] 走一遍。初始 x8=0，x1=2。第一轮 LDRSW 读到 −2，CMP 按 32 位计算与零的差并更新标志；CSEL 看到有符号 GT 不成立，选 xzr。计数减为 1，累加器仍为 0，跳回。第二轮读到 5，CSEL 保留 5，计数减为 0，累加器变成 5，循环退出并返回 5。如果 n 初始为 0，CBZ 直接跳到 done，全程没有读取数组。

NZCV 的四位依次表示负、零、无符号进位以及有符号溢出。cmp w9,#0 等价于 subs wzr,w9,#0；丢弃差值，保留标志。gt 检查 Z=0 且 N=V；无符号“大于”用 hi，检查 C=1 且 Z=0。把负数的位模式当作无符号数比较，会改变保留下来的元素。

沿两条隐含依赖分别划线：CMP → CSEL 决定累加哪个数；SUBS → B.NE 决定是否继续。中间普通 ADD 保留标志，所以 B.NE 读到计数器的 Z。cbz/cbnz 则直接测试一个寄存器是否为零；b label 无条件改变执行位置。

调用：为什么要保存 x30

call_scaled:
    str x30, [sp, #-16]!
    bl  scaled
    sub x0, x0, #1
    ldr x30, [sp], #16
    ret

沿 call_scaled(3,5) 跟踪：先把 SP 减 16，把入站返回地址写入新栈顶的 8 字节，栈保持 16 字节对齐。BL 跳到 scaled，并把下一条 SUB 的地址写入 x30。scaled 的 RET 依此回到 SUB，此时 x0=15。减一得到 14，从栈恢复原 x30，再把 SP 加 16。末尾 RET 默认跳到 x30，从而回到外层调用者。

比较两个寻址符号：[sp,#-16]! 在访问之前更新 SP，[sp],#16 在访问之后更新 SP。bl 调用已知目标，若目标地址在寄存器中，可用 blr xN；br xN 跳转并保留现有链接地址。

相同的“加”，数据类型可以不同

double_add:  fadd d0, d0, d1
             ret
lanes:       add  v0.4s, v0.4s, v1.4s
             ret

第一例把两个双精度标量相加，1.5 与 2.25 得到 3.75。第二例把每个 128 位向量分成四个 32 位整数通道，逐通道相加。[1,2,3,4] 加上 [10,20,30,40] 得到 [11,22,33,44]。某个通道溢出的进位不会流入邻居。读指令时把操作数写法和助记符一起看，add x0,… 与 add v0.4s,… 操作的数据布局不同。

复验与源码阅读

七个完整函数在实验 IR。从根目录运行，工具取自 LLVM 22.1.8 的 PATH，或用 LLC、LLVM_MC、LLVM_OBJDUMP 指定路径。先在 basics.s 中按函数名找最终汇编，再回到 isel.txt 看选择后的依赖。encoding.txt 保留无别名反汇编和重定位信息，便于核对 MUL、CMP 与 BL 的目标。

out=evidence/arm64-basics
mkdir -p "$out"
"${LLC:-llc}" -mtriple=aarch64-unknown-linux-gnu -mcpu=generic -O2 \
  -global-isel=0 -fast-isel=0 -verify-machineinstrs -print-after=aarch64-isel \
  experiments/arm64-basics.ll -o "$out/basics.s" 2> "$out/isel.txt"
"${LLVM_MC:-llvm-mc}" -triple=aarch64-unknown-linux-gnu -filetype=obj \
  "$out/basics.s" -o "$out/basics.o"
"${LLVM_OBJDUMP:-llvm-objdump}" -dr --disassembler-options=no-aliases \
  "$out/basics.o" > "$out/encoding.txt"
