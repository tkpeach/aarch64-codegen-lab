相邻常量怎样改变 ADD 的操作数

第 4 天 · P2-C2 · LLVM 22.1.8

机制问题

为什么同样的 add i64 只改一个常量，就可能改变所选指令及其输入依赖？

本节产出为一份按函数对齐的三行观察表和一段机制解释。

从寄存器移位转向立即数

第 1 天的 ADDXrs 把寄存器值左移后相加。今天固定函数为 x + K，调用者只传 x。看见汇编中的 lsl 时，先问被移位的是寄存器还是指令里的常量字段。

ADDXri 的两个立即数操作数可读作 u 和 s，加数等于 u × 2s。u 是 12 位无符号数，s 只能取 0 或 12。例如 u=3、s=12 表示 12288。寄存器编号、COPY、返回指令和汇编伪指令要分别看，单数文本行容易误判。

受控实验

完整输入 day4-add-imm.ll

define i64 @plus_4095(i64 %x) {
  %sum = add i64 %x, 4095
  ret i64 %sum
}

define i64 @plus_4096(i64 %x) {
  %sum = add i64 %x, 4096
  ret i64 %sum
}

define i64 @plus_4097(i64 %x) {
  %sum = add i64 %x, 4097
  ret i64 %sum
}

从项目根目录运行。先用 "${LLC:-llc}" --version 核对 22.1.8。脚本固定 Linux AArch64、generic、-O2、SelectionDAG 和机器指令验证器。需要指定工具时先设置 export LLC=/opt/homebrew/opt/llvm@22/bin/llc。

bash experiments/replay-selection.sh 4

打开 evidence/day4/selection.txt，按函数名定位选择后的机器基本块，再在同目录 final.s 中找到对应函数。

读一遍选择后的数据流

4095   ADDXri  %x, 4095, 0
4096   ADDXri  %x, 1, 12
4097   MOVi32imm 4097 → SUBREG_TO_REG → ADDXrr

上面省略了 COPY 和寄存器编号。4096 刚好是 1 左移 12 位。4097 的高低两部分都有置位，任何一种移位都装不下整个值。本次选择器把它准备到寄存器，最终可见 mov w8, #4097 和 add x0, x0, x8。阶段中的 SUBREG_TO_REG 描述子寄存器关系，最终汇编里没有同名指令。

从 AArch64InstrInfo.td 的 defm ADD 跟到 AArch64InstrFormats.td 的 AddSub，比较 Xri 与 Xrr 的输入。沿立即数操作数定义查找移位选择与立即数字段，把字段限制对应到具体 K。
