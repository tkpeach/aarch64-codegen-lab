机制问题

本节产出为一份可交接的短报告与一条尚待回答的问题。

短报告样例 · x + K

研究问题是相邻的正整数如何改变加数来源。LLVM 22.1.8、AArch64 Linux、generic、-O2、SelectionDAG 下，K=4096 的选择后指令使用立即数 1 和移位量 12。K=4097 时，常量经寄存器进入 ADDXrr。两份最终汇编分别可见一条立即数加法，以及准备常量再相加。源码阅读入口为 ADD 的 Xri/Xrr 操作数定义。

从 AArch64InstrInfo.td 的 defm ADD 跟到 AArch64InstrFormats.td 的 AddSub，比较 Xri 与 Xrr 的输入。沿立即数操作数定义查找移位选择与立即数字段，把字段限制对应到具体 K。

这个对照支持操作数编码影响所选形态。它能说明这组输入的机器指令依赖；若要声称某种形态执行更快，还需要指定微架构和性能证据。

从项目根目录运行。先用 "${LLC:-llc}" --version 核对 22.1.8。脚本固定 Linux AArch64、generic、-O2、SelectionDAG 和机器指令验证器。需要指定工具时先设置 export LLC=/opt/homebrew/opt/llvm@22/bin/llc。

bash experiments/replay-selection.sh 4

打开 evidence/day4/selection.txt，按函数名定位选择后的机器基本块，再在同目录 final.s 中找到对应函数。

交接实测记录

在临时目录只复制 project.yaml 和归档 JSONL，使用项目已有的 RepoFoundry 执行一次导入和一次 context。重建的上下文与当前项目逐项相同。新检出时需先按第 1 天笔记准备工具；本次恢复复用了现成环境。常规续接省去导入，只需一次 context 即可取得 Work 和最近证据。

Work 可直接找出验证范围；学习者对 P2-C1 的逐题原答与反馈仍需打开对应 Markdown。选择后的机器指令保存在忽略的 evidence/ 中，新工作区须从仓库中的 IR 和命令重新生成。仍待检验的问题是：接手者能否仅凭这些入口独立解释一个陌生案例？第 6 天的原答和阶段复核将为此提供证据。
