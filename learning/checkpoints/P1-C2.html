从匹配条件到可验证的预测

第 2 天 · LLVM 22.1.8 · SelectionDAG · P1-C2

这组题要回答什么

总问题。把移位量从编译期常量改成运行时参数后，同一个移位加法会怎样被 AArch64 选择器处理？你将用哪条匹配条件解释预测，又会用什么观察区分「选择时已经发生」和「后续才发生」？

综合产出。写出一份简短预测，串起「输入变化 → 受到影响的条件 → 预期机器指令 → 可以推翻判断的输出」。下面的三个答题框分别收集这条推理链的三部分。可以边查源码边答。

先读已知基线

这份 i64 IR 是上一课已经解释并核对过的例子。

define i64 @add_shift(i64 %a, i64 %b) {
entry:
  %shifted = shl i64 %b, 3
  %sum = add i64 %a, %shifted
  ret i64 %sum
}

ADD 的第二个输入指向 SHL 的结果。基线在选择后看到 ADDXrs，最终汇编是 add x0, x0, x1, lsl #3。前者说明指令选择结束时已经出现带移位的机器指令，后者确认最终输出的汇编形态。

上一课的 i128 变体提供了另一个观察。整段计算需要 EXTRXrri、ADDSXrs 和 ADCXr，其中低半部仍把移位折叠进加法。用这组结果练习区分两个判断：「整体计算有几条指令」和「局部移位是否折叠」。

复验已知基线时，从项目根目录运行：

mkdir -p evidence/day2
"${LLC:-llc}" -mtriple=aarch64-unknown-linux-gnu -mcpu=generic -O2 \
  -verify-machineinstrs -print-after=aarch64-isel \
  experiments/add-shift.ll -o evidence/day2/baseline.s 2> evidence/day2/baseline-isel.txt

怎样找会影响预测的条件

  1. 先在纸上圈出变化的一个操作数。问自己加法节点的依赖结构有没有变化，以及选择器能从移位节点的第二个操作数知道什么。
  2. 沿基线的 ADDXrs 回到 defm ADD 和 AddSub::Xrs，再沿 arith_shifted_reg64 找回调。只需引用能区分两个输入的检查，函数名可以查。指令定义 · 操作数回调
  3. 预测时可以用「一条带移位的加法」或「移位 → 加法」这样的示意，也可以写机器 opcode。把源码能支持的判断和待实测的预测分别写出来。

盲预测 · 给定 IR

只改变移位量的来源。%a、%b、%amount 均为符号参数。保持 LLVM 22.1.8、aarch64-unknown-linux-gnu、generic、-O2。先作答，再核对这个输入的实际输出。

define i64 @add_shift_variable(i64 %a, i64 %b, i64 %amount) {
entry:
  %shifted = shl i64 %b, %amount
  %sum = add i64 %a, %shifted
  ret i64 %sum
}
