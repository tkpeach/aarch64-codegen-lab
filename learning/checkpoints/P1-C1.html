从 LLVM IR 到 AArch64 指令

第 1 天 · LLVM 22.1.8 · SelectionDAG · 约 60–75 分钟

读讲解（15 分钟） · 复验对照（15–20 分钟） · 追源码并作答（30–40 分钟）

同一个表达式在三个阶段的表示

  1. 构图。SelectionDAGBuilder 访问 IR 指令，把值与依赖转换成带类型的 DAG 节点和边。可以从返回值依赖的计算节点向下追踪操作数。
  2. 整形。SelectionDAGISel 驱动 DAG combine 和 legalization。Combine 重写图形状，legalization 处理目标不直接支持的类型和操作。读匹配规则时，要追踪选择器实际收到的图形状。
  3. 选择。AArch64 selector 把可匹配的子图替换成目标机器节点。一个匹配可以覆盖多层节点。之后机器指令还会经过寄存器分配等 pass，最终由汇编输出展示。

用单独的减法走一遍

define i64 @diff(i64 %a, i64 %b) {
  %d = sub i64 %a, %b
  ret i64 %d
}

从源码可把整数减法追到接收两个 i64 值的 ISD::SUB。llc -print-after=aarch64-isel 的日志标题写着 IR Dump，正文展示的是指令选择后的机器基本块。这个阶段已经同时出现物理寄存器和虚拟寄存器，可以按参数、计算、返回的顺序追踪数据。

bb.0 (%ir-block.0):
  liveins: $x0, $x1
  %1:gpr64 = COPY $x1
  %0:gpr64 = COPY $x0
  %2:gpr64 = SUBSXrr %0:gpr64, %1:gpr64, implicit-def dead $nzcv
  $x0 = COPY %2:gpr64
  RET_ReallyLR implicit $x0
  1. 入口参数。liveins 是 LLVM Machine IR 的通用标记，列出进入这个机器基本块时已有可用值的物理寄存器。在这个入口块，AArch64 调用约定把两个参数放在 $x0 和 $x1，两条 COPY 分别将它们引入虚拟寄存器 %0 和 %1。 调用约定在后端降低函数参数时就确定了物理入口寄存器，所以寄存器分配前也会看到 $x0 和 $x1。分配器随后为 %0、%1 等虚拟寄存器选择实际寄存器，并遵守已有的物理寄存器约束。若源和目标最终落在同一寄存器，入口的 COPY 可以消掉。LLVM MIR 格式参考
  2. 计算。SUBSXrr 读取两个虚拟寄存器，写出 %2，并隐式定义 $nzcv。dead 表示标志位没有后续使用。最终汇编中的计算是 sub x0, x0, x1。
  3. 返回。$x0 = COPY %2:gpr64 把结果放进调用约定规定的返回值寄存器。AArch64 特有的伪指令 RET_ReallyLR 用 implicit $x0 表示返回时需要保留这个结果。最终的 ret 通过链接寄存器 LR（x30）取得返回地址。AArch64 返回指令定义

下一组对照沿用这条数据流。把结果加宽到两个 64 位字后，第二条计算要读取 $nzcv，返回也要通过 $x0 和 $x1 交付两个分量。

受控对照 · 只把减法加宽到 i128

输入仍是一条减法 IR，计算值由 64 位变成 128 位。保持 triple、CPU、优化级别和 selector 配置相同。对照两次选择后的机器指令，再看最终汇编。

define i128 @diff_wide(i128 %a, i128 %b) {
  %d = sub i128 %a, %b
  ret i128 %d
}
%4:gpr64 = SUBSXrr %0:gpr64, %2:gpr64, implicit-def $nzcv
%5:gpr64 = SBCXr %1:gpr64, %3:gpr64, implicit $nzcv

把操作数写成高低两个 64 位字。低半部先计算差，若低半部借位，高半部的差还要减 1。选择后第一条指令定义 $nzcv，第二条隐式读取它。这条依赖在窄减法中没有后续使用，在宽减法中参与计算。最终汇编对应 subs x0, x0, x2 和 sbc x1, x1, x3。

手算一次 0x1_0000000000000000 - 1，把高低半部与两条机器指令对上。这个对照给出了一个边界反例：即使 IR 只有一条算术指令，目标计算仍可能需要多条指令。

1. 构图 · 从 IR 操作数拿到 DAG 值

这里的「DAG 值」是 SDValue，即对一个节点的某个输出的引用。它由生产该值的 SDNode * 和从零开始的结果编号 ResNo 组成。节点描述一次操作，操作数边引用生产节点的具体结果。SDValue 定义

减法节点只产出一个 i64 结果，%d 对应它的结果 0。普通 load 可以同时产出读到的数据和用于约束内存操作顺序的 chain。同一个节点可因此产生两个不同的 SDValue。

SDValue Op1 = getValue(I.getOperand(0));
SDValue Op2 = getValue(I.getOperand(1));
SDValue BinNodeValue = DAG.getNode(Opcode, getCurSDLoc(), Op1.getValueType(),
                                   Op1, Op2, Flags);
setValue(&I, BinNodeValue);

getValue 查到两个操作数的 DAG 值，getNode 用传入的 opcode 和第一个操作数的类型创建结果，setValue 将结果关联回当前 IR 值。移位走旁边的 visitShift，从下面这行开始看目标如何决定移位量的类型。

EVT ShiftTy = DAG.getTargetLoweringInfo().getShiftAmountTy(
    Op1.getValueType(), DAG.getDataLayout());

减法规则如何变成匹配表

前面实测的 SUBSXrr 可以追到 AArch64 的这条独立 Pat。左边描述要匹配的 DAG 形状，右边描述要构造的机器节点。$Rn 和 $Rm 把输入绑定到输出指令的对应操作数。AArch64 的减法规则

def : Pat<(sub GPR64:$Rn, GPR64:$Rm),
          (SUBSXrr GPR64:$Rn, GPR64:$Rm)>;

右边的 SUBSXrr 来自 defm SUBS : AddSubS<…> 展开的 Xrr。Defs = [NZCV] 属于指令定义，对应机器指令日志里的隐式定义。生成器把 pattern 转成检查、记录操作数和输出机器节点等 matcher 步骤，再对所有规则一起优化并写表。AddSubS 定义 · matcher 生成过程

用仓库里的 sub-matcher.td 隔离一条形状相同的规则，把输出 opcode 简化为 SUBrr。以下表项由 LLVM 22.1.8 的 llvm-tblgen 实际生成，省略了源模式和目标模式的注释。这张表只包含教学目标的一条规则。完整 AArch64 表会和其他模式一起优化，可能共用 opcode 分派和检查。

/*      0*/ OPC_CheckOpcode, TARGET_VAL(ISD::SUB),
/*      3*/ OPC_RecordChild0, // #0 = $lhs
/*      4*/ OPC_RecordChild1, // #1 = $rhs
/*      5*/ OPC_MorphNodeTo1None, TARGET_VAL(::SUBrr),
                 MVT::i64, 2/*#Ops*/, 0, 1,
    0
  1. OPC_CheckOpcode 检查当前 DAG 根是否是 ISD::SUB。TARGET_VAL 将 opcode 编入表项。
  2. OPC_RecordChild0 和 OPC_RecordChild1 把两个输入 SDValue 存入临时记录的槽位 0、1。它们对应规则里的 $lhs、$rhs。
  3. OPC_MorphNodeTo1None 读取目标 opcode、一个 i64 结果和两个操作数槽位，把当前 DAG 根改写成 SUBrr 机器节点。这里的 None 表示这个表项没有 chain 或 glue 标志。

SelectCodeCommon 按上述顺序读表，记录的操作数直接供机器节点使用。在完整匹配表中，检查失败时可退回到还有备选的匹配作用域，继续试下一条候选。SelectCodeCommon

作答后复盘 · 怎样选源码细节、怎样找

前三题围绕同一个判断：移位和加法在哪个阶段合成一条机器指令，为什么这次能合成？源码符号用于定位证据，可以查阅。先用自己的话说清因果，再附上具体出处。

  1. 先确认匹配器要看到的结构。构图题要说明加法的第二个操作数来自移位结果，这条边直接影响能否匹配。查构图时，先在 SelectionDAGBuilder.cpp 搜 visitShift 和 visitBinary，看每处怎样取操作数和建立结果。移位量类型仅在它影响你的判断时展开。构图源码
  2. 再找让结果分叉的条件。复盘时从选择后的 opcode ADDXrs 倒查。先在 AArch64InstrInfo.td 搜 defm ADD，再到 AArch64InstrFormats.td 的 AddSub 中找 Xrs。defm 会拼接名字，因此直接搜完整 opcode 可能找不到定义。顺着 arith_shifted_reg64 找 ComplexPattern 的回调名 SelectArithShiftedRegister，再跟到 SelectShiftedRegister。在普通移位分支里，常量检查决定能否编码，isWorthFoldingALU 决定是否值得折叠。本例移位只有一个使用点，满足其中的单次使用条件。ADD 入口 · 回调声明 · 条件实现
  3. 最后验证结论发生在哪个阶段。验证题关心你选的观察点能否回答问题。选择后日志已经出现一条 ADDXrs，就能说明这次折叠在选择结束时已经发生。若同一位置看到独立的移位和普通加法，则应修正这个判断。最终汇编用于复核输出。

可用一句话自查：「我选的这段代码能解释输入形状、区分匹配成功与失败，或证明变化在哪个阶段发生吗？」若都不能，先跳过这段实现。复核时可以边查边写，函数名以能定位你的依据为准。

主练习 · 移位加法（add_shift）

第 1–3 题统一使用下方完整的 add_shift IR。把 %a 和 %b 当作任意 i64 参数，移位量固定为 3。运行条件为 LLVM 22.1.8、aarch64-unknown-linux-gnu、generic 和 -O2。先按源码推导，作答后再核对运行结果。

define i64 @add_shift(i64 %a, i64 %b) {
entry:
  %shifted = shl i64 %b, 3
  %sum = add i64 %a, %shifted
  ret i64 %sum
}

这里用符号描述 DAG，不必给参数代入数字。可以每个节点写一行。以讲解中的窄减法为例，可写 n0 = ISD::SUB i64(a, b)，再写「IR 结果 %d 对应 n0 的第 0 个结果，构图入口是 SelectionDAGBuilder::visitBinary」。练习里如果一个节点引用另一个节点的输出，用自取的节点名标出这条边即可。

写出改后的 IR 行，说明改动检验的是哪项条件。其余 IR 和运行参数沿用第 1–3 题。本题只要求设计输入。
